# Week4 WIL

## 레포지토리 계층
- **역할**: 데이터베이스와 직접 소통하며 데이터를 조작하는 계층이다. 서비스 계층에서 결정된 비지니스 로직을 실제 데이터베이스에 적용하는 역할을 수행한다.
- **주요 기능 (CRUD)**: 데이터 조작의 핵심 기능인 **생성 (Create)**, **조회 (Read)**, **수정 (Update)**, **삭제 (Delete)** 네 가지 기능을 주로 구현한다.
- **JPA 활용**: CRUD 기능은 JPA가 제공하는 기능을 이용하여 구현할 수 있다. 과거에는 직접 SQL을 작성해야 했지만, JPA를 통해 생성, 수정, 삭제는 별도의 SQL 작성 없이 간편하게 구현 가능하다. 조회 기능은 JPQL이라는 JPA 전용 쿼리 문법을 사용해야 한다.

## 엔티티 매니저 (Entity Manager)
- **생성**: JPA는 application.yml 파일 정보를 기반으로 엔티티 매니저 객체를 생성한다.
- **역할**: 우리 대신 데이터베이스와 직접 소통하는 객체이다.
    - **주요 업무**: 새로 생성한 엔티티 객체를 데이터베이스에 추가한다.
    - 데이터 베이스에서 조회한 데이터로 엔티티 객체를 만든다.
    - 엔티티 객체에 대한 수정, 삭제 사항을 데이터베이스에 반영한다.

## 트랜잭션 (Transaction)
- **개념**: 데이터베이스에서 비롯된 개념으로, 여러 데이터베이스 조작을 하나의 논리적인 작업 단위로 묶는 것이다.
- **원자성 (Atomicity)**: 트랜잭션으로 묶인 모든 작업은 반드시 모두 성공하거나 모두 실패해야한다.
- **커밋 (Commit)**: 트랜잭션이 성공적으로 끝나면 모든 변경 사항을 데이터베이스에 영구적으로 반영한다.
- **롤백 (Rollback)**: 트랜잭션 실행 중 에러가 발생하거나 명시적으로 롤백을 요청하면 트랜잭션 시작 시점으로 되돌아간다.
- **JPA와 트랜잭션**: JPA를 사용하여 엔티티 매니저로 데이터베이스 조작을 수행할 때는 반드시 트랜잭션 안에서 동작해야한다. `@Transactional` 어노테이션을 사용하여 메서드 단위로 트랜잭션을 설정할 수 있다.

## 영속성 컨텍스트 (Persistence Context)
- **역할**: 자바 애플리케이션과 데이터베이스 사이에서 JPA가 데이터 조작을 돕기 위해 사용하는 중간 임시 공간이다.
- **주요 기능**
    - **1차 캐시 (First-Level Cache)**: 데이터베이스에서 조회한 엔티티 객체를 임시로 보관하여 동일한 객체를 다시 조회할 때 데이터베이스 쿼리를 보내지 않고 영속석 컨텍스트에서 바로 가져와 성능을 향상시킨다.
    - **쓰기 지연 (Write Behind)**: 엔티티에 대한 모든 병경 사항(생성, 수정, 삭제)을 즉시 데이터베이스에 반영하지 않고 영속성 컨텍스트에 임시로 보관한다. 트랜잭션이 커밋될 때 영속성 컨텍스트에 저장된 변경 사항들을 종합하여 한 번에 SQL을 생성하고 데이터베이스에 반영한다. 이를 통해 여러 번의 SQL 실행을 줄여 최적화할 수 있다.
    - **변경 감지 (Dirty Checking)**: 영속성 컨텍스트에 로드된 엔티티 객체의 상태 변경을 JPA가 감지하여 트랜잭션 커밋 시 자동으로 UPDATE 쿼리를 생성하고 데이터베이스에 반영한다.

## 레포지토리 계층 구현 (CRUD)
- **`@Repository` 어노테이션**: 레포지토리 클래스를 스프링 빈으로 등록하기 위해 상용한다. `@Component` 어노테이션을 포함하고 있어 컴포넌트 스캔 시 빈으로 등록된다.
- **`@PersistenceContext` 어노테이션**: 영속성 컨텍스트에 접근할 엔티티 매니저를 주입받을 때 사용한다.
    - **데이터 생성 (Create)**: 새로운 엔티티 객체를 생성한다. `em.persist(entity)` 메서드를 호출하여 영속성 컨텍스트에 엔티티를 등록한다. 트랜잭션 커밋 시 `INSERT` 쿼리가 실행된다.
    - **데이터 조회 (Read)**
        - **단건 조회**: `em.find(EntityType.class, id)` 메서드를 사용하여 엔티티 클래스와 기본 키 값을 기준으로 하나의 엔티티를 조회한다. 영속성 컨텍스트에 데이터가 있으면 캐시된 데이터를 반환하고, 없으면 데이터베이스에서 조회한다.
        - **다건 조회 (모든 데이터)**: `em.createQuery("select e from Entity as e", EntityType.class).getResultList()` 메서드를 사용하여 모든 엔티티를 조회한다. JPQL이라는 JPA 전용 쿼리 언어를 사용한다.
        - **조건 조회** `em.createQuery("select e from Entity as e where e.field = :parameterName", EntityType.class).setParameter("parameterName", value).getResultList()` 메서드를 사용하여 특정 조건을 만족하는 엔티티를 조회한다. JPQL의 WHERE절과 파라미터를 사용한다. JPQL에서는 객체 필드에 접근하며, `where e.user = :user`와 같이 객체 비교가 가능하다.
    - **데이터 수정 (Update)**: 수정할 엔티티를 `em.find()` 등으로 조회하여 영속성 컨텍스트에 로드한다. 조회한 엔티티 객체의 필드 값을 수정한다. 일반적으로 엔티티 클래스 내부에 데이터 변경을 위한 메서드를 추가하여 사용한다.
    - **데이터 삭제 (Delete)**: 삭제할 엔티티를 `em.find()` 등으로 조회하여 영속성 컨텍스트에 로드한다. `em.remove(entity)` 메서드를 호출하여 영속성 컨텍스트에서 엔티티를 삭제 상태로 만든다. 트랜잭션 커밋 시 DELETE 쿼리가 자동으로 생성되고 실행된다.

## 레포지토리 테스트
- **테스트 환경 설정**: `@SpringBootTest` 어노테이션과 `webEnvironment = WebEnvironment.DEFINED_PORT` 옵션을 사용하여 실제 스프링 부트 애플리케이션 환경과 유사하게 테스트 환경을 구성한다. H2 데이터베이스 관리자 콘솔 (로컬호스트 8080)을 통해 데이터 변경 결과를 눈으로 확인할 수 있다.
- **`@AfterAll`**: 모든 테스트 실행이 끝난 후 실행되는 메서드를 정의하여 애플리케이션 종료를 방지하고 H2 콘솔을 계속 사용할 수 있도록 한다.
- **테스트 시 유의 사항**
    - JPA 코드는 반드시 `@Transactional` 어노테이션으로 트랜잭션 범위 내에서 실행되어야 한다.
    - 테스트 환경에서는 기본적으로 테스트 종료 후 자동으로 롤백이 수행된다. 데이터베이스에 데이터가 실제로 반영되었는지 확인하려면 `@Rollback(false)` 옵션을 추가해야한다.
    - 영속성 컨텍스트의 1차 캐시 기능으로 인해 예상과 다르게 SELECT 쿼리가 나가지 않을 수 있다. 테스트 목적으로 `em.flush()` (변경 사항 강제 반영) 및 `em.clear()` (영속성 컨텍스트 비우기) 메서드를 사용할 수 있다.

## JPQL
- **객체 지향 쿼리 언어**: SQL과 유사한 문법을 사용하지만 테이블 대신 엔티티 클래스를 대상으로 쿼리를 작성한다.
- **변수 사용**: 쿼리 내부에서 `:변수명` 형태로 변수를 사용하고, `em.setParameter("변수명", 값)` 메서드를 통해 값을 바인딩한다.
- **객체 비교**: JPQL에서는 `where e.user = :user`와 같이 객체 필드를 직접 비교할 수 있으며, JPA가 자동으로 적절한 SQL로 변환해 준다.
